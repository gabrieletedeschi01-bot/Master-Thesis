# MATLAB Source Code

## Main script

`Safety_Critical_Vehicle_Platooning.m` is the main MATLAB entry point for the continuous-time platoon simulation. It contains the parameter setup, initial-condition generation, local controller and safety-filter functions, platoon dynamics, numerical integration, post-processing, and plotting commands.

## Execution flow

1. **Initialize the workspace** — clears variables and figures.
2. **Set model and controller parameters** — defines the number of vehicles, desired spacing, controller gains, acceleration limit, headway-like parameter, CBF gain, and mesoscopic coefficients.
3. **Build initial conditions** — creates a state vector containing position, velocity, and an additional internal state for each vehicle. Initial positions include seeded random offsets; initial velocities depend on the vehicle index.
4. **Define the leader reference** — the reference speed is 15 before 5 seconds and 5 from 5 seconds onward.
5. **Compute control commands** — the local function `compute_control` calculates nominal commands, filtered commands, and requested upper bounds for the followers.
6. **Apply the QP filter** — `quadprog` minimizes deviation from the nominal command subject to the implemented inequality and acceleration limits.
7. **Integrate the dynamics** — `ode45` calls `platoon_dyn` over the configured 30-second horizon.
8. **Reconstruct outputs** — the script recomputes control signals and evaluates distance and CBF-related quantities along the returned time vector.
9. **Generate figures** — plots distances, leader and relative speeds, control inputs, CBF intervention magnitude, and the CBF safety function.

## Main functions

- `compute_control(...)`: computes the nominal command, filtered command, and requested CBF-related bound. It uses a leader-tracking law for the first vehicle and a follower law plus a scalar quadratic program for each follower.
- `platoon_dyn(...)`: unpacks the state vector, calls `compute_control`, and returns the continuous-time derivatives of positions, velocities, and internal states. The function also contains the current disturbance logic.
- `macrofz(...)`: computes mesoscopic terms from accumulated spacing and relative-velocity quantities.

These functions are defined locally in the script rather than in separate `.m` files.

## Disturbances in the current source

The following logic is currently embedded directly in the script and dynamics function:

- **Leader reference-speed change:** reference speed changes from 15 to 5 at (t = 5) s.
- **Sinusoidal leader-acceleration term:** for (5 < t < 30) s, the leader acceleration derivative is modified by adding (5\sin(2\pi\,0.1t)).
- **Additional follower perturbation:** for vehicle index 10 and (10 < t < 15) s, an additional (-10) term is applied to that vehicle's acceleration derivative.

The third item targets one indexed vehicle in the current implementation; do not describe it as a disturbance applied to multiple rear vehicles unless the code is changed. Also, the sinusoidal term is part of the current dynamics regardless of the intended scenario name.

## Figures generated by the script

The script creates MATLAB figures for:

- Inter-vehicle distance-related trajectories.
- Leader speed and follower-to-preceding-vehicle speed differences.
- Nominal, filtered, and requested control inputs.
- Difference between nominal and filtered control.
- CBF safety-function values.

The current script does not automatically save all figures to the scenario folders. The three committed PDFs in Scenario 3 are existing exports, and their correspondence to a particular code revision and parameter configuration should be confirmed before scientific interpretation.

## Requirements and run instructions

- MATLAB.
- Optimization Toolbox for `quadprog`.

Open this script in MATLAB and run it. Review the parameters and embedded disturbance conditions first. Inspect the command-window output, including QP timing statistics, and confirm that the solver calls complete successfully. Do not assume that a successful script execution proves the CBF constraints or the intended scenario comparison are valid.

## Known reproducibility limitation

The script currently does not expose separate top-level switches for enabling/disabling the CBF filter, braking perturbation, and sinusoidal leader disturbance. As a result, the scenario folders describe intended experiments, but Scenario 1 and Scenario 2 cannot be reproduced simply by selecting a documented flag in the current script. Add and validate explicit switches before using this script as a repeatable three-scenario experiment runner.
